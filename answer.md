### Q1. Role of Frontend (FE)

Frontend is the part of a web application that the user sees on the screen. It is what users interact with when they open a website or app.

User Interface
Frontend is responsible for the design of the application. It shows buttons, text, images, forms, colors, and layouts so the user can understand and use the app easily.

User Interaction
Whenever a user clicks a button, types in a form, or moves to another page, the frontend handles these actions. It also shows messages like errors, success messages, and loading states.

Communication with Backend
Frontend sends data to the backend and receives data from it. For example, when a user logs in, the frontend sends the email and password to the backend and then displays the result.

### Q2. Role of Backend (BE)

Backend is the part of the application that works behind the scenes. It is not visible to the user but it controls how data and logic work.

Server-side Processing
Backend receives requests from the frontend, processes them, and sends back responses. It decides what should happen when a user performs an action.

Database Handling
Backend stores and retrieves data from the database. User details, orders, products, and messages are all saved and fetched by the backend.

Security and Authentication
Backend checks whether a user is allowed to access something. It handles login, passwords, tokens, and makes sure data is protected from unauthorized users.

### Q3. Business Logic

Business logic is the set of rules that decides how an application should behave in real-life situations. It controls how data is processed based on the business needs.

Examples:

In an online shopping app, a user cannot place an order if the product is out of stock.

In a bank app, a user cannot withdraw more money than what is available in their account.

In a food delivery app, orders cannot be placed if the restaurant is closed.

These rules are part of business logic.

### Q4. Client–Server Model

The client–server model explains how users and servers communicate in a web application.

Client
The client is the user’s device, such as a browser or mobile app.

Server
The server is a computer that receives requests and sends back data.

How they communicate
The client sends a request (like login or get data) to the server. The server processes it and sends a response back to the client.

### Q5. Three-Tier Architecture

Three-tier architecture divides a web application into three layers.

Presentation Layer
This is the frontend. It shows the user interface.

Application (Business) Layer
This is the backend logic. It handles rules, processing, and decisions.

Data Layer
This is the database. It stores all the information.

Why it is used
It makes the system easier to manage, update, and scale. Each layer has its own job.

### Q6. JavaScript as a Backend Language

JavaScript is used on the backend using Node.js.

Performance
Node.js is fast and can handle many users at the same time.

Ecosystem
JavaScript has many libraries and tools that make development easier.

Popular Backend Frameworks
Some popular JavaScript backend frameworks are Express.js, NestJS, and Fastify.
